# 兵种可视化编辑器（Unit Visual Editor）

给**不懂技术的策划**用的兵种调整工具：改生命/攻击/射程/移速、换图标与动画贴图、调训练冷却与解锁等级，全在一个窗口里，并且能一眼对比全部兵种。

- 代码位置（唯一真源）：`GitHub\Unit Editor\UnitVisualEditor\`
- 接入方式：`CageFight\Assets\Editor\UnitSystem\UnitVisualEditor` 是一个**目录联接（junction）**，指向 `Unit Editor\UnitVisualEditor`。工程里没有多出任何实体脚本文件，也没有改动任何既有文件。
- 姊妹工具：图鉴编辑器（`Illustration Editor`），两者互不依赖。

---

## 一、怎么打开

Unity 顶部菜单 **工具 → 兵种可视化编辑器**（快捷键 `Ctrl + Alt + U`）。

打开后会自动扫描两类数据：

| 数据 | 位置 | 管什么 |
|---|---|---|
| 单位预制体 | `Assets/RemoteResource/Prefabricated body/<种族>/` | **战斗数值**（预制体上的 `GameObjectProperty` 等组件） |
| 训练配置 | `Assets/RemoteResource/TroopDefinitions/<种族>/` | **训练规则**（`TroopDefinition`）：兵营阶级（解锁等级）、冷却、产出、维护费、图标、AI 威胁阶级 |

> 目录里的子弹（`Bullet`、`Cat Bullet`…）、建筑（`Build`）、特效（`Vfx`）、法术（`Magic`）、UI 会被自动跳过；没有 `GameObjectProperty` 的预制体也不会当成兵种。

## 三、常见任务怎么做

### 0. 按「训练 ID」找兵种（关卡/敌方队伍配置里引用的就是它）
- 左栏搜索框直接输入 ID（如 `cat_knight`）即可筛选；**输入完整 ID 会自动定位并选中**那个兵种
- 搜索范围包含：训练 ID / 名称 / 预制体名 / 种族 / 资源路径
- 左栏勾上 **「行内显示训练 ID」** 后，每行会多显示一行 `ID: xxx`（默认开启），一眼对照
- 右栏**数值对比表新增「训练 ID」列**，可点表头排序，便于检查 ID 是否重复/遗漏
- 中栏标题里的 **训练 ID 可以选中复制**
- 体检会报 **「训练 ID 重复」**（关卡/敌方队伍配置按 id 引用兵种，重复会让引用落到不确定的兵种上）与「训练配置缺 id」
- **批量补全**：左栏底部「批量补全训练 ID（空的 + 重复的）」按钮 —— 空的按单位预制体名生成、重复的追加 `_2`/`_3`，统一用**小写+下划线**风格（与工程现有 `cat_knight`、`miner_rat` 一致）；执行前自动备份、可 `Ctrl+Z`、明细打到 Console
- 「一键修复」补 id 也走**同一套规范化 + 唯一性**规则（不会再写出带空格的原始预制体名），并且同一轮体检里给多个重复条目算出的新 id 互不相同

### 1. 调一个兵种的数值
1. 左栏找到它（搜索支持名称 / ID / 预制体名 / 资源键），点一下
2. 中栏「战斗数值」直接改：
   - **生存**：`maxHp`、`defense`、`magicDefense`
   - **输出**：`atk`、`magicAtk`、`atkRate`、攻击范围（网格 X/Y）、远程开关、投射物键、基础未命中率
   - **机动**：`moveSpeed`、击退/抗击退、吸血、占地尺寸、血条保持时间
3. 右栏「数值对比表」立刻能看到它在全体兵种里的位置
4. 工具栏 **保存全部**（`Ctrl+S`）落盘

> **重要提醒**：角色的实际出手节奏由**攻击动画事件**驱动（`CharacterAI` 在动画事件里发射投射物），所以 `atkRate` 并不等于角色的攻速——它目前只影响哨塔（按每秒射击次数）和攻速类 Buff（精准/狂暴）的计算。工具里所有地方都没有假装算 DPS。

### 1.5 「兵营阶级」「AI 威胁阶级」「普通/黑暗兵营」到底谁管什么

这几个字段很容易混，工程里的实际作用（有代码依据）。**工具里说的"阶级"一律指兵营阶级**：

| 字段 | 谁在用 | 作用 |
|---|---|---|
| **兵营阶级 `unlockLevel`**（1-3） | 玩家侧：`BuildingTraining.GetTroop(row, index)` 只取 `UnlockLevel == row` 的兵种，兵营面板按它分第 1/2/3 排；`TroopTrainingPanel` 用 `Level < UnlockLevel` 显示"未解锁"；`TeamCommander` 也用 `UnlockLevel > barracks.Level` 过滤 AI 能产的兵 | **玩家在兵营第几排看到它、要兵营几级才能训练** —— 这就是工具里列表排序、筛选、对比表「兵营阶」列用的"阶级" |
| **AI 威胁阶级 `tier`**（1-3） | **只有敌方 AI**：`TeamCommander.ScoreTroop()` 里 `score = max(0, Tier) * 10` | 阶级越高敌方 AI 越倾向生产它（另加"克制玩家主力 +100、定位不重复 +5"）。**和兵营排数、玩家解锁完全无关**，工具里只在「AI 威胁阶级」这一处显示 |
| **普通 / 黑暗兵营** | **在兵营预制体上，不在兵种上**：`BuildingTraining.isDarkBarracks` + 该预制体的 `troops` 数组 | 勾了 `isDarkBarracks` 的建筑按**黑暗兵营等级** `darkBarracksLevel` 结算；普通兵营用 `barracksLevel`。兵种挂在哪个兵营的 `troops` 里，就在哪个兵营面板出现（可以两边都挂） |

工具里怎么看：
- 左栏列表：组内**按兵营阶级排序**，行内显示 `兵营1阶`（若 AI 阶级与兵营阶级不一致，会补一个 `·AI2` 的小标记）；筛选下拉是 **全部兵营阶级 / 兵营 1-3 阶 / 无训练配置**
- 左栏 **兵营筛选**：`全部兵营 / 普通兵营 / 黑暗兵营 / 未挂兵营`；旁边是 **分组方式**：`按种族分组 / 按兵营分组`（按兵营分组会分成【普通兵营】【黑暗兵营】【未挂任何兵营】三节）
- 左栏每行右侧有 **归属角标**：`普通`（绿）/ `黑暗`（紫）/ `未挂`（黄），不用选中就能看出它在哪种兵营出现
- 筛选行下面一行是 **归属分布**：`归属分布（全部 N 个）：普通 A　黑暗 B　未挂 C`（按整个目录统计，不受当前筛选影响；数字由工具按兵营预制体实时算出来）
- 中栏「训练配置」区有一行 **兵营归属**：显示 `普通兵营 Mouse Barracks1` / `黑暗兵营 …` / 没挂时标红提示"玩家在兵营界面永远看不到它"
- 右栏对比表有 **「兵营阶」列**（= 兵营阶级，可点表头排序）、**「AI阶」列**（= AI 权重阶级）和 **「兵营」列**（普通 / 黑暗 / 两者 / —，可点表头排序）
- 体检会报 **「训练配置没挂到任何兵营」**、**「兵营阶级超出面板范围」**（0/4 这类在面板上任何一排都不出现）、**「AI 阶级与兵营阶级不匹配」**
- 体检的「同阶数值离群」也是按**兵营阶级**分桶比中位数（同一排解锁的兵才是互相竞争的）
- 兵营预制体位置：`Assets/RemoteResource/Prefabricated body/Build/`（改归属要在兵营预制体的 `BuildingTraining.troops` 里拖，或在工具里看归属确认后去预制体改）

### 2. 改训练规则（兵营里怎么出这个兵）
中栏「训练配置」：显示名、训练 ID、定位标签（近战/远程/攻城/肉盾/辅助）、威胁权重、**兵营阶级（解锁兵营等级 1-3）**、**AI 威胁阶级（1-3，敌方 AI 选兵用）**、单次产出数量、训练冷却、维护费、是否需要拥有后才能训练。

### 3. 换图标 / 动画贴图 / 音效
中栏「精灵图 / 动画 / 音效」+「训练配置里的资源键」，每行都是「缩略图 + 键 + 搜索按钮」：
- 点 **搜索** 打开**可任意缩放 / 最大化 / 停靠的选键窗口**（标题栏写明正在填哪个字段、哪个兵种）：列出该种类（Sprite / Prefab / AudioClip / AnimatorController / AnimationClip）的全部键，带缩略图，**点一行即填入**；窗口不关可以连续给多个字段选键，拖「行高」滑块能把缩略图放大看清细节
- 键不存在时会**红字提示**，出包会加载失败
- `StageAudio` 最多 8 个音效键

### 4. 一次调一批兵种（平衡调整主力）
1. 左栏**勾选**要动的兵种（或先筛选后点工具栏「全选显示项」）
2. 左栏 **批量操作 ▾**：
   - 整体调整：生命值 / 攻击力 / 魔攻 / 移速 / 训练冷却 **×1.1 或 ×0.9**
   - 把选中兵种的数值**复制给其它兵种**（数值模板复用）
3. 没勾选任何兵种时，「整体调整」作用于**全部兵种**
4. 执行前会弹确认 + 自动备份，可 `Ctrl+Z`

### 5. 用 Excel 整表调数值
- **表格 → 导出数值表 CSV**：一行一个兵种，40+ 列（训练配置 + 全部战斗数值），UTF-8 带 BOM，Excel 直接打开不乱码
- 在 Excel 里改完 → **表格 → 从 CSV 导入**：先弹预览（能匹配几行、哪些行对不上、缺哪些列），确认后才写
  - 匹配键是**第一列「单位预制体名」**，改名就对不上（会跳过并提示）
  - **空单元格 = 保持原值**
  - 导入前自动备份，可 `Ctrl+Z`

### 6. 数据体检（右栏）
能查出：预制体找不到、缺 `GameObjectProperty`、生命/移速为 0、攻击范围含 0、攻速系数为 0、远程却没投射物、各类资源键失效、训练冷却为 0、两个兵种共用同一单位键、**同兵营阶级数值离群**（偏离同阶级中位数 ±60%）、兵营阶级越界（0/4）、AI 阶级与兵营阶级不匹配、有预制体却没有训练配置……

- **一键修复**：补训练配置里空的 `displayName` / `id` / `prefabKey`，把越界的兵营阶级 / AI 阶级夹回 1~3，把冷却 / 产出数量的非法值改成 1，修正能唯一确定的投射物资源键。**战斗数值一律不自动改**——工具不替你做平衡决策
- 每条问题可「定位」到对应兵种（留在体检页，中栏会跟着切过去）
- **导出报告**：存成 txt 交给程序

### 7. 为缺失的兵种新建训练配置
左栏底部 **「为缺失的兵种新建训练配置」**：会给有预制体但没有 `TroopDefinition` 的兵种批量建好资产（`id` / 显示名 / 单位预制体键按预制体名填好，兵营阶级 1、冷却 5 秒、产出 1）。

> 新建之后还需要在**兵营预制体的 `BuildingTraining.Troops`** 里挂上，玩家才能在兵营里训练到它。
> （**要做"从零一个新兵种"，用下面第 9 条那条龙，它连兵营挂载一起做。**）

### 9. 从零做一个新兵种（工具栏「新建兵种…」，一条龙）

**这是本工具唯一会创建预制体的入口**，也是游戏工程里第一次有"造兵种"这件事：以前只能手工复制预制体再一个个字段接。

```
工具栏「新建兵种…」→
① 从哪个兵种复制：选种族 + 模板兵种（默认就是左栏当前选中的那个）
② 叫什么：名字（= 预制体文件名 + 资源键 + 默认训练 ID，建议英文/拼音）+ 显示名（可中文）+ 训练 ID（留空自动生成、重名自动 _2/_3）
③ 美术 Key：默认「沿用模板」（同美术换数值）；也可以自己填贴图/动画/图标/子弹/语音（带键选择器）
④ 训练规则：普通/黑暗兵营、阶级（= 解锁等级 1..3）、冷却、单次产出、维护费、威胁权重、兵种标签
⑤ 接哪几条线：建 TroopDefinition / 登记 PrefabRegistry / 挂进兵营 BuildingTraining.troops（默认全开）
⑥ 先点「试运行」看计划（会写哪些文件、动哪些已有资产、建完还差什么）→ 再点「新建」
```

**它一次替你做完这些事**（每步都在结果里如实汇报）：

| 步骤 | 做什么 | 依据 |
|---|---|---|
| ① 复制预制体 | 从模板复制到 `Assets/RemoteResource/Prefabricated body/<种族>/<名字>.prefab`：16 个根组件、4 个共享行为子预制体（`Attack/FindEnemy/FindPath/Move`）、`ShootPoint`、能力组件一起带过来 | `PrefabUtility.LoadPrefabContents` / `SaveAsPrefabAsset` |
| ② 改根节点名字 | **必须改**：资源键 = **根 GameObject 名字**（不是文件名），不改名会跟模板在注册表里撞键 | `RegistryBuilder.BuildPrefabs` 用 `prefab.name` 当 key |
| ③ 改美术 Key | 只有选了"不沿用模板"才改：`StageTexture.spriteKey` / `StageAnimatorController.animatorControllerKey` / `GameObjectProperty.atkObj`（子弹）/ `StageAudio.audioKey1` | 与运行时组件字段一一对应 |
| ④ Addressables | 加进 `Remote Prefab <种族>` 分组（找不到同种族分组才退回默认组），地址 = 资源键 | `AddressableAssetSettings.CreateOrMoveEntry` |
| ⑤ 登记 PrefabRegistry | 只**加一条**（key + 强引用 + AssetReference 的 GUID），不重建整表 | 照 `EngineerRegistryWriter` 的做法：`SerializedObject` 插数组元素 |
| ⑥ 建训练配置 | `TroopDefinitions/<种族>/<名字>.asset`，填 id / 显示名 / prefabKey / 图标 / 动画 / 贴图 / 阶级 / 标签 / 冷却 / 产出 / 维护 / 威胁 | 字段是 private `[SerializeField]`，只能走 `SerializedObject` |
| ⑦ 挂进兵营 | 按**种族资产** `RaceDefinition.buildings` 里的 `Barracks(1)/DarkBarracks(2)` 条目找到兵营预制体，把新配置追加进 `BuildingTraining.troops` | 归属在兵营预制体上，不在兵种上 |

**动到已有资产的两处（PrefabRegistry、兵营预制体）写之前都会自动备份到 `UnitBackups`。**

**建完还差什么**（工具做不到，会一条条列出来）：Addressables 分组没找到时要手工加；关卡预载要在关卡编辑器里把新兵种带进本局；图鉴条目归图鉴编辑器；新美术资源要先登记进各自注册表。

### 8. 撤销 / 备份
- 所有字段写入都走 `SerializedObject`（与 Inspector 完全一致），`Ctrl+Z` 可撤销
- 工具栏 **保存全部** 会提示备份；批量调值 / CSV 导入 / 一键修复前**自动备份**到
  `Unit Editor\UnitBackups\<资产名>_日期_时间_原因.asset|prefab`
- 备份目录在**工程之外**（不会被 Unity 导入、不会进包）
- 设置页可改备份目录、保留份数，或「立即备份全部兵种」

## 四、红线

1. **`TroopDefinition.id`** 是存档与关卡配置的稳定标识，改了会影响已有引用。
2. **两个兵种共用一个单位预制体键**时，数值其实是同一份预制体——改一个两条都会变（体检会警告）。
3. **资源键必须来自注册表**，自己编的键出包加载不到。
4. **生命缩放**：`maxHp` / `atk` / `magicAtk` 在运行时按 `1.1^(兵营等级-1)` 缩放，所以预制体里填的是**等级 1 的基准值**；防御/攻速/击退/移速**不缩放**。
5. 「运行时修正字段」（`damageMultiplier`、`critChance`、`armor`…）由 Buff 管理，`ResetRuntimeState` 每次复用都会归位，改预制体只影响初始快照——工具里默认折叠起来了。

## 五、给程序看的部分

| 文件 | 作用 |
|---|---|
| `UnitEditorWindow.cs` | 主窗口：三栏布局、工具栏、列表、表单、对比表、批量操作、CSV/备份流程 |
| `UnitEditorModel.cs` | 兵种扫描与目录（预制体 + TroopDefinition 合并）、5 张注册表的统一资源键索引、数值读写会话、备份 |
| `UnitEditorValidation.cs` | 兵种体检规则 + 一键修复 + 同兵营阶级离群检测 |
| `UnitEditorCsv.cs` | 数值表导出/导入（RFC4180、UTF-8 BOM/GBK 兼容、先预览后写入） |
| `UnitEditorUI.cs` / `UnitKeyPickerPopup.cs` | 绘制工具箱、通用资源键搜索弹窗 |

- 编译归属：`Assets/Editor/CageFightEditor.asmdef`（已引用 `CageFightRuntime`，可直接用 `GameObjectProperty` / `CharacterHealth` / `StageTexture` / `StageAnimatorController` / `StageAudio` / `UnitAntiOverlap` / `TroopDefinition`）。目录里没有 asmdef，不会新增程序集。
- 写入范围：`TroopDefinition` 资产（`.asset`）与单位预制体（`.prefab`），都是策划调数值的正常落点；**不碰任何运行时代码**。
- 私有 `[SerializeField]` 字段（如 `CharacterHealth.deathAngularSpeed`）也是通过 `SerializedObject` 读写，不受访问级别限制。

### R6 — 修「一键修复点了修不掉，同一条错误永久复报」

反馈：检查各编辑器的体检与一键修复是否正常。

**问题**：体检里的 `U-ATKOBJ-INVALID`（投射物键不在注册表里，可修）点一键修复会提示「已修复 1 处」，
但**同一条错误立刻又出现**，反复点永远修不掉；对比表的投射物列、CSV 导出的 `atkObj` 列也一直是旧值。

**根因**：一键修复的这条修复改的是**预制体**上的 `GameObjectProperty.atkObj`
（`UnitEditorValidation.FixProjectileKey`），而体检读的是 `UnitStats` **数值快照**
（按 `PrefabPath` 缓存）。修复路径**没有失效这份快照**，于是校验永远拿到修复前的值。

| | |
|---|---|
| 缓存本体 | `UnitEditorModel.GetStats()` 命中 `_statsCache` 就直接返回；`InvalidateStats()` 清它 |
| 唯独漏掉这条 | `UnitEditorWindow.RunAutoFix()` 调完 `ApplySafeFixes` 只置了 `_issuesDirty`，**没调 `InvalidateStats()`** |
| 其他路径都调了 | `UnitEditorWindow.cs` 的 `:395 / 892 / 1341 / 2249 / 2327`，以及 `UnitEditorCsv.cs:422` |

**修法**：`RunAutoFix()` 里 `ApplySafeFixes` 之后补一句 `_catalog.InvalidateStats();`。
`GetStats` 缓存未命中时走的是 `UnitStatsReader.Read(PrefabPath)`（重新读盘），所以清缓存就够，
不需要额外刷新别的对象。

> 通用检查办法：**每条 `Fixable = true` 的规则，点完一键修复之后必须不再触发。**
> 缓存类状态（数值快照 / 缩略图 / 统计）只要有一条写路径忘了失效，就表现为"修了等于没修"。

### R7 — 「新建兵种…」：从零做一个兵种，一次把预制体 + 训练配置 + 资源键 + 兵营挂载接好

问题：本工具一直只会**改**（改 `TroopDefinition`、改已有预制体的组件字段），
**造预制体**这件事在游戏工程 + 8 个工具仓库里**从来没有先例**（全库 `SaveAsPrefabAsset` 0 命中）。
于是"加一个新兵种"只能手工：复制预制体 → 改名 → 一个个字段改 Key → 建训练配置 → 想资源键 → 拖进兵营，
中间任何一步漏了都表现为"游戏里就是不出这个兵"，而且不报错。

| 改动 | 说明 |
|---|---|
| 工具栏新增 **「新建兵种…」** | 弹出向导窗口（`UnitEditorNewUnitWindow`），带**试运行**：先给计划，再落盘 |
| 一条龙 | 复制预制体 → 改根节点名字 →（可选）改美术 Key → 加 Addressables 分组 → 登记 PrefabRegistry → 建 TroopDefinition → 挂进兵营 `BuildingTraining.troops` |
| 安全 | 动已有资产（PrefabRegistry / 兵营预制体）前自动备份；全程 `Undo` 可用；建完在列表里自动选中新兵种 |
| 「还差什么」清单 | Addressables 分组、关卡预载、图鉴、新美术资源 —— 工具做不到的**明确列出来**，不留隐式期望 |

**为什么"复制"是安全策略**：一个单位预制体是 16 个根组件 + 4 个共享行为子预制体（`Attack/FindEnemy/FindPath/Move`）
+ 一个 `ShootPoint` + 能力组件。手工重建极容易漏，而**少了 `CharacterHealth` 就完全打不掉血**
（它是唯一的 `ICollide`，`DamageSource.OnTriggerEnter2D` 拿不到就静默丢弃）。
复制模板把这些原样带走，需要变的只有"身份"（名字）与"外观"（美术 Key）。

> **怎么验的**（写盘那一步只有 Unity 能验，所以把能验的都验了）：
>
> **① 纯逻辑内核单测 51 条全过**：`UnitEditorUnitFactory.cs` 里的 `UnitFactoryCore`（命名清理、查重、路径、
> 计划与清单生成）**从真文件原样抽出**编进独立控制台程序，断言覆盖：训练 ID 清理
> **与工程既有 `SanitizeTrainingId` 逐条对齐**（空格 / 短横 / 点号 / 连续分隔符 / 首尾 / 空 / 纯符号 / 数字）、
> 文件名清理（中文保留、非法字符替换）、`MakeUniqueId` 的 `_2/_3` 与大小写不敏感、计划里的路径与 id、
> 同名预制体拦截、缺模板 / 缺名字 / 负冷却拦截、id 撞车提醒、阶级越界夹取、
> 自己填的 Key 不存在要提醒（**都真实存在时不误报**）、中文预制体名提醒 id 也会变中文、
> 不建训练配置时不写兵营、没有兵营时写进"还差什么"。
>
> **自测当场抓到两个真问题**（都已修）：
> 1. **根节点没改名** —— 资源键是**根 GameObject 名字**而不是文件名，复制出来的预制体若不改名，
>    在注册表里会跟模板撞键（`RegistryBuilder` 遇到重名只警告并跳过）。已改成复制后先改名再保存。
> 2. **Key 存在性标志含义含糊** —— 原来一个 `SpriteKeyExists` 既可能指模板的 Key、也可能指用户填的 Key，
>    全靠调用方自觉，结果"填了个不存在的 Key"永远查不出来。已拆成两组（模板的 / 自己填的），
>    由纯逻辑按"这一次用哪个"取值。
>
> **② 逆向核对过运行时契约**（免得造出"看着对、进游戏不动"的预制体）：
> `CharacterAI` / `CharacterHealth` 是硬要求；单位根节点必须在 layer 0（子弹在 layer 6 `DamageSource`，
> 碰撞矩阵才配得上）；`TroopDefinition` 全部字段是 private `[SerializeField]`（只能 `SerializedObject` 写）；
> 兵营归属在兵营预制体的 `BuildingTraining.troops` 上，不在兵种上。
>
> 工具侧编译闸 ✔（9 个源文件）+ 源码卫生 ✔。
>
> **未验的部分说清楚**：**没有真的创建过一个兵种**（造资产只能在你机器上的 Unity 里跑）——
> 向导排版、试运行输出、以及真正落盘后的预制体 / 注册表 / 兵营数组，都要切回 Unity 点一次才知道。
