# 关卡可视化编辑器（Level Visual Editor）

给策划用的**关卡编辑器**：看战场、调数值、查配置问题，全程不用碰代码、不用记字段名。

- 代码位置（唯一真源）：`GitHub\Level Editor\LevelVisualEditor\`
- 接入方式：`CageFight\Assets\Editor\StageSystem\LevelVisualEditor` 是一个**目录联接（junction）**，指向上面的源码目录。工程里没有多出任何实体脚本文件，也没有改动任何原有文件。
- 面向的游戏功能：`StageConfig` 关卡资产（`Assets/RemoteResource/Stages/StageN.asset`）+ 选关 / 胜负 / 敌方 AI / 玩家经济

> 与**图鉴编辑器 / 兵种编辑器**同一套做法与同一套视觉语言，策划在两个工具之间不用重新学。

---

## 一、怎么打开

| 方式 | 操作 |
|---|---|
| 菜单 | Unity 顶部菜单 **工具 → 关卡可视化编辑器**（快捷键 `Ctrl + Alt + L`） |
| 资产右键 | Project 面板里右键 `StageN.asset` → **打开关卡可视化编辑器** |
| 自动 | 在 Project 面板点选 `StageN.asset`，已打开的工具窗口会自动切到这一关 |
| 兵种一览 | 工具栏**最左边**的「关卡 \| 兵种一览」切页（看每个兵种出现在哪些关、出现概率、首次出现，并能就地改头像与显示名） |

打开后会自动加载上次编辑的关卡；第一次打开会加载编号最小的那一关。

### 工具栏「关卡 ▾」：新增 / 复制 / 删除关卡

| 菜单项 | 做什么 |
|---|---|
| **新建关卡（从当前场景导出）…** | 弹一个「新建关卡」小窗口：填编号 / 玩法类型 / 防守时限 / 图标 → 调**现成的**「关卡构建 → 创建新关卡」（`StageExporter`）把**当前打开的场景**导成新资产。工具不复制一份场景导出逻辑，两边行为永远一致 |
| **复制当前关卡为新关卡…** | 同一个窗口的另一页：把当前关卡整个拷一份（**预摆对象 / 敌方队伍 / 资源清单都在**），适合"照着一关改一关"，不用回场景重新导出 |
| **删除当前关卡…** | 二次确认（写明会删掉几个预摆、几支敌队）→ 自动备份 → `AssetDatabase.MoveAssetToTrash`（**进系统回收站，不是硬删**）→ 切到剩下的第一个关卡 |

三个都只**新增 / 移除关卡资产本身**，不动工程里任何原有脚本。

> 「新建关卡」窗口会自动填**下一个可用编号**（取现有正式关最大编号 +1，≥880 的测试关不参与推算），
> 并在路径已被占用时把按钮改成 **覆盖创建（先备份）** —— 覆盖前自动备份一份到 StageBackups。


### 左栏：关卡卡片带

每张卡片：关卡编号、玩法类型、主时限、敌队数、预摆对象数、右上角**上架角标**（已上架 / 未上架 / 测试关）、右上角最右的**注释按钮**（有注释时高亮并带点，点开写备注）、右侧**问题角标**（错=红、警=黄、无问题=绿），左侧竖条是这一关最严重的体检级别。

筛选：搜索（编号/名称）、玩法类型、状态（只看有错的 / 只看没上架的 / 只看本地测试关）。左栏底部显示注释数量并可打开**注释总览**（R1.30）。

### 中栏：本关出现的兵种（本工具的主工作区）

这一屏回答「**这一关敌方会出什么兵、什么时候出、本关强度多少**」，而且**可以直接改**。

分类轴是**兵种解锁等级**，也就是游戏内训练面板的「三排阶数」：

> `BuildingTraining.GetTroop(row, index)` 的注释写明「面板按解锁等级 1/2/3 分排」，
> `TroopTrainingPanel.Refresh()` 也是 `for (int row = 1; row <= 3; row++)` 逐排填充。
> **不是** `TroopDefinition.tier` —— 那个字段在 `TeamCommander.ScoreTroop` 里被当 AI 打分权重用（`score = Tier * 10`），
> 全工程分布也很偏（34 / 6 / 4），分不出三阶。卡片第二行把 AI 那两个数（阶梯 / 威胁）单独标出来，避免混淆。

结构是「队伍 → 普通/黑暗兵营 → 1/2/3 阶 → 兵种卡片」：

```
第 N 支队伍   种族 Cat   编号 2  起始 200  每秒 100  Balanced   [白名单 3 个 / 自动解锁全部兵种]
├ 普通兵营  Cat Barracks1   共 11 个兵种
│  ├ 1 阶（需兵营 Lv1 解锁） 3 个
│  │   [图标] Cat apprentice   [解锁(秒) 0] [定位] [移出白名单]
│  │   本阶还能加：2 个   ＋Cat son   ＋Fat cat
│  ├ 2 阶（需兵营 Lv2 解锁） 5 个
│  └ 3 阶（需兵营 Lv3 解锁） 3 个
└ 黑暗兵营  Cat DarkBarracks  共 N 个兵种
   └ 1 / 2 / 3 阶 …
```

| 区块 | 内容 |
|---|---|
| **队伍头** | 种族 / 队伍编号 / 起始金币 / 每秒金币 / 策略；右侧角标写明当前是「白名单 N 个」还是「自动解锁全部兵种」 |
| **兵营分组** | **普通兵营**与**黑暗兵营**各一组（按 `RaceDefinition.buildings` 里的 `Barracks` / `DarkBarracks` 条目找到预制体），组头写明预制体键与兵种数 |
| **阶分组** | 每组内按 **1 阶 / 2 阶 / 3 阶**分三个小节，标题写明「需兵营 LvN 解锁」与数量 |
| **兵种卡片** | 图标（按 `iconKey` 从 SpriteRegistry 取，取不到则红框 +「图标键无效」标签）；名字 / Id；第二行是定位标签（近战/远程/攻城/肉盾/辅助）+ `N 阶` + 需兵营 Lv / 维护费 / 冷却 / 单次产出 / AI 阶梯·威胁；第三行是**本关实际数值** |
| **本关实际数值** | 从**兵种预制体**上的 `GameObjectProperty` 读基础生命/攻击/魔攻，再乘 `1.1^(敌方兵营等级-1)` —— 与运行时单位出生时注入的缩放一致；同时显示基础值、倍数与移速 |
| **场上预摆** | 预摆对象按预制体键分组，区分**兵种 / 建筑**，显示 ×数量、队伍归属、生命/攻击、占地；兵种会用它自己的图标；键不在注册表标红；坐标越界与 `side = 0` 单独给告警条 |
| **清空全部预摆对象** | 「场上预摆」标题下面那行的右侧按钮：**整关清空** `StageConfig.objects`。与上方的搜索 / 筛选**无关**；有确认弹窗（写明数量）、可 `Ctrl+Z` 撤销、点「保存」才落盘 |

**折叠**：队伍 / 兵营 / 阶 / 场上预摆 每一层都可以点标题折叠（队伍用左边的 ▼▶ 小按钮）。
工具栏右侧有「全部展开 / 全部收起」。折叠状态记在 `EditorPrefs` 里，关掉窗口再打开还是收起的。

**增删都在这一屏**（只改本关 `StageN.asset`，**不动兵营预制体**）：

- **白名单模式**（名单非空）：每张卡片可改「解锁 N 秒」、可「移出白名单」；每个阶下面有「本阶还能加：N 个」的快捷加入按钮；队伍级「清空白名单」可整体改回自动模式
- **自动模式**（名单为空）：列出该种族兵营预制体上挂的**全部**兵种，每张卡片可「加入白名单」，每个阶还有「把本阶 N 个兵全部加入白名单」
- 另有「＋ 加入白名单」菜单（按 普通/黑暗兵营 × 1/2/3 阶 分组列出）与「搜索兵种…」（可停靠的兵种选择窗口）
- 白名单一旦非空，本局敌方**只能**出名单里的兵 —— 界面上有明确提示
- **场上预摆**整块可一键清空（见上表），清空后体检会立刻重算

> **为什么不做战场画布**：这张地图是 **72×8 的一条横线**，画成图信息量很低；而关卡数值真正决定的是"每个队伍出哪些兵、什么时候解锁、强度多少"。
> 空间类的配置问题交给「体检」报警（例如 Stage4/5/9999 的预摆对象 y 全是负数、整体落在运行时地图外）。

- **右栏可以收起**：右栏页签行最右端有 **✕** —— 收起整条右栏（连分割条一起收，中栏立刻拿到全部宽度）；收起后工具栏会出现 **▸ 展开右栏**。收起状态记在 EditorPrefs 里，关掉重开还是收起的。

### 右栏三个页签

**① 数值** —— 分组表单，点选即改（每个分区标题可点击折叠，每支队伍块也可折叠）：

- **玩法与时限**：玩法类型（防守/进攻/Boss）、三种时限、关卡编号
- **阵地**：启用我方大本营 + 坐标、敌我基地距离（旁边直接写推导出的敌方大本营 x 与半场分界）、Boss 出生格与预制体键
- **本关敌方等级**：5 个等级（旁边换算成 ×1.1^(等级-1) 的倍率）
- **玩家经济**：启用收入曲线、开局每秒金币、收入增长阶段（增删改，每个阶段旁边给出"到阶段末约为 N/秒"）
- **敌方队伍**：增删队伍、编号、种族（下拉读 `RaceDefinition.Id`）、起始金币、每秒金币、策略、阵地锚点、**普通兵营 / 黑暗兵营 / 哨塔上限**（三者各算各的）、**建筑槽位**（类型 + 坐标，在玩家半场的当场标红；「自动编排」可按 普通兵营 / 黑暗兵营 / 哨塔 三个数量生成）、**兵种白名单**（兵种选择器 + 解锁秒数）
- **通关奖励**（**大师模式**全额 + **普通模式**可单独自定义，不勾就是大师的一半；旁边实时显示普通实发与大师补发的差额；R1.29 起还能**按关卡类型存模板**并一键套用到所有同类型关 —— 新建关卡会自动套用该类型模板）、**展示**（关卡图标、选关展示图；导游对话见下方说明）
- **全局规则**（从工程里的 `GlobalRuleDefinition` 资产里挑）

**② 体检** —— 见下文。

**③ 设置** —— 注册表读取情况、Addressables 上架地址、地图尺寸来源、备份目录与份数、地图尺寸来源、当前关卡信息。

## 三、数据体检（本工具最值钱的部分）

体检覆盖**全部关卡**，每条结论都能在右栏「体检」页里点「定位」跳到对应关卡。

### 错误（会让玩家看到错误内容或让关卡永远赢不了）

| 规则 | 依据 |
|---|---|
| 关卡编号无效 / 资产文件名与 `stageId` 不一致 | 选关按地址 `Stage{编号}` 连续加载，错位就会加载到别的关 |
| **关卡编号不连续（有缺口）** | `StageConfigLoader.cs:71-99` 遇到第一个缺口就停止加载 → 缺口之后的关卡玩家永远看不到 |
| **正式关没登记 Addressables** | 同上；**可用工具栏「上架」或「一键修复」登记**（地址 `Stage{编号}` + 标签 `StartupPreload`，写的是分组资产） |
| 进攻/Boss 关生成不出敌方大本营 | 敌方大本营取 `enemyTeams[0].raceId`（`StageGoalTracker.cs:166-201`），缺失时只打一条警告 → 永远无法获胜 |
| Boss 关没配 `bossPrefabKey` / 键不在注册表 | `StageGoalTracker.cs:224-231`，缺失则 Boss 不生成 |
| 敌方队伍 `raceId` 为空 / 种族不存在 | `GameplayState` 要求 `raceId` 非空才启用该队 |
| **兵种白名单里有空条目** | 运行时直接 `unlock.Troop.Id`（`TeamCommander.cs:1137`）→ **NullReferenceException**，整队出兵判断中断 |
| 我方大本营 / Boss / 槽位坐标越界 | 越界即位置合法性检查失败 |
| **建筑槽位与其它建筑占地重叠 / 间距不足 1 格**（R1.21 新增） | 运行时会**直接不建造**这一格：`TryBuildSlot` 先试 ±`positionJitter` 抖动位置、再试槽位原坐标，两次都要过 `TryPlaceAt → HasBuildingNeighbor(..., margin = 1)`（与其它建筑**至少隔 1 格**）与逐格占位检查（`TeamCommander.cs:719-731`、`:879-883`、`:938-977`），都不过就每 5 秒重试 + 一条警告 → 现象是**这一格的哨塔 / 兵营永远不会建**。占地大小按种族建筑的 `occupySpace` 实算，槽位坐标 = 建筑左下角 |
| 预摆对象的预制体键不在注册表里 | 运行时只警告并跳过（`StageObjectInstantiator.cs:48-49`），关卡内容**静默缺失** |
| 六份资源键清单里有键不在对应注册表 | 键解析不出来时**不会中断进关** —— `ResourceManager` 打一条「未找到匹配的 Addressable 资源，已跳过」就跳过它。真实后果是**依赖这个键的功能静默失效**（用它的代码通常是 `if (x == null) return;`，连报错都没有）。**具体后果取决于谁在用这个键，不能一概而论** |
| **本关要生成大本营，但它的种族建筑不在 `prefabs` 清单里** | 键没预载 → `GetGameObject` 返回 null → `TryInstantiateFriendlyMainBase` **LogError 并 return false** → 整个 `InstantiateStage` 返回 false → **进关只有一张空地图**（`ResourceManager.cs:627-683` / `StageObjectInstantiator.cs:129-136` / `LoadingState.cs:87-91`） |

> **遇到「预制体资源键不在注册表里」怎么查**（Stage5 / Stage6 那次排查的实战流程，值得留着）：
>
> 1. **键指向什么** —— 拿键去 `PrefabRegistry.asset` 搜 `- key: <键>`。搜不到再看 Addressables 有没有**同名地址**：
>    **有地址不等于能当 GameObject 用** —— `Huge cheese` 就有地址，但它指向的是**动画贴图**，
>    所以以 `Type: GameObject` 解析照样失败（这就是那条运行时警告的来源）。
> 2. **谁在用它** —— 全工程搜这个键的**字符串字面量**（`"<键>"`），定位到那个 `[ResourceKey]` 字段。
> 3. **它怎么进的关卡清单** —— 导出器（`StageResourceKeyCollector`）扫的是预制体上 `[ResourceKey]` 字段的**实时值**，
>    所以**代码里的默认值写错也会被忠实地收进清单**，并且只有含那个预制体的关卡才中招。
>    实例：`JieruiAbility.cheesePrefabKey` 的默认值写成了 `"Huge cheese"`，而真正的奶酪预制体叫 `cheese`
>    → Stage5 / Stage6 的清单里就多了个死键（这两关恰好含 jierui）。
> 4. **怎么修** —— 把那个字段的值改成**在 PrefabRegistry 里登记过**的键，再把关卡清单里的旧键换掉。
>    **工具改不了这一步**：一键修复只做加法（只追加缺的键），删 / 改清单里的键得手工做，或者用「关卡构建」重新导出该关。

### 警告（配置与运行时行为不一致）

| 规则 | 依据 |
|---|---|
| `hasFriendlyMainBaseGridPosition = false` | 运行时不会生成我方大本营，**且"被拆即败"判定整体失效**（`StageGoalTracker.cs:53`） |
| **配了 Boss 预制体但玩法类型不是 Boss 关** | `StageGoalTracker.cs:64-79` 的 switch 只在 `Boss` 分支生成 → 这个 Boss 永远不会出现 |
| 敌方队伍编号 < 2 | 运行时按 `max(2, teamId)` 处理（`TeamCommander.cs:81`），实际编号与配置不符 |
| 敌方队伍经济全为 0 | 整局造不出任何东西 |
| 敌方没有任何建造计划 | 槽位为空且普通兵营/黑暗兵营/哨塔上限都是 0 → 不会建建筑、也不会出兵 |
| **某类型槽位比该类型上限多**（R1.27 新增，普通兵营 / 黑暗兵营 / 哨塔**分开数**） | 运行时的上限是**硬约束**（`TeamCommander.IsSlotTypeAtCap`）：槽位表决定「在哪、按什么顺序建」，上限决定「最多几座」。超出上限的槽位不会开工（位置留着，上限调大后仍会建）→ 现象是"设计了 5 个黑暗兵营槽位，实际只建了 2 个" |
| **建筑槽位在玩家半场** | 敌方 AI 遇到 `x < 半场分界` 的槽位直接跳过 |
| **预摆对象 `side = 0`** | `TeamRules.IsEnemySide(0) == true`，会被当敌方并注入敌方等级（`StageObjectInstantiator.cs:238`） |
| **预摆对象落在运行时地图外**（汇总为一条，含坐标范围） | 世界坐标直赋、不吸附网格 |
| 兵种白名单里某兵种解锁时间 > 本关时限 | 本局永远出不来 |
| 起始金币/每秒金币为负、白名单重复兵种、展示图 > 4 张等 | 各自的字段约束 |
| **只有第一支队伍会生成敌方大本营** | 第 2 支及以后只用 `homeGridPosition` 当阵地锚点 |
| **资源清单里缺种族建筑预制体（缺的不是大本营）** | 玩家运行时才选种族，兵营 / 哨塔按所选种族现查种族资产的 `Buildings` 表；缺了 `BuildingButton` 会「回落默认建筑」（`BuildingButton.cs:78`）→ 本局兵种预载与建筑外观都不对，但**不会**阻断进关 |

### 提示

启用了还是没启用收入曲线（分别走哪条公式）、收入阶段不封口 / 在时限之后 / 每步增量为 0、没有关卡图标、通关奖励为 0、空关卡、本地测试关等。

## 七、红线（会让线上出问题的操作）

1. **不要随便改关卡编号（`stageId`）**：存档进度、选关地址、「下一关」全都按编号走。
2. **资源键必须来自注册表**：预制体 → `PrefabRegistry`，Sprite → `SpriteRegistry`，音频/纹理/动画 → 各自的 Registry。自己编的键编辑器里能填，出包后加载不到。
3. **关卡编号不能有缺口**：选关遇到第一个缺口就停止加载。
4. **改了资源键要重新构建 Addressables**。
5. **不要用「关卡构建 → 创建新关卡」重新导出已调好数值的关卡**：导出器是 `CreateAsset` 覆盖式的（`StageExporter.cs:99`），会把敌方队伍、经济、奖励、导游对话、全局规则**全部重置**。要改数值就在本工具里改。

```
CageFight\Assets\Editor\StageSystem\.gitignore
    /LevelVisualEditor
    /LevelVisualEditor.meta
    /.gitignore          ← 自己也排除自己，所以这个文件也不会进版本库
```

> /Assets/Editor/StageSystem/LevelVisualEditor
> /Assets/Editor/StageSystem/LevelVisualEditor.meta
> ```

**概率口径（界面上也写着，不让人误当成精确值）：**

### R1.27 — 建筑槽位：**普通兵营与黑暗兵营分开计算**（运行时 + 工具两侧都改了）

起因：**黑暗兵营实际上从来没被建出来过**。查下来不是数据问题，是记账方式错了 ——

| 现象 | 原因 |
|---|---|
| 21 个关卡里**一个黑暗兵营槽位都没有**，AI 也几乎不建黑暗兵营 | 槽位表里没有 `DarkBarracks`，动态扩张那条路又进不去（见下） |
| 就算手填了黑暗兵营槽位，也永远不开工 | `CountBarracks()` 把**挂 `BuildingTraining` 的建筑全算一类**（普通兵营 + 黑暗兵营），再和 `maxBarracks` 比；普通兵营槽位一填满 `CountBarracks() == maxBarracks` → `canExpandBarracks` 为假 → **黑暗兵营那条分支整个进不去**（老代码把黑暗兵营分支写在 `if (canExpandBarracks)` 里面） |

改法：**两类兵营各记各的账、各受各的上限约束**，互不占名额。

**运行时（动了游戏代码，2 个文件）**：

| 文件 | 改动 |
|---|---|
| `StageConfig.cs` | 新增 `[Min(0)] public int maxDarkBarracks = 2;`（`EnemyTeamConfig` 里，紧跟 `maxBarracks`）。**默认 2** 不是 0：默认 0 会让"黑暗兵营永不出现"从"事实上不出现"变成"写死不允许"，比改动前更差 |
| `TeamCommander.cs` | ① `CountBarracks()` → `CountBarracks(bool dark)`，按 `BuildingTraining.IsDarkBarracks` 分类计数；② `canBuildBarracks` 与 `canBuildDarkBarracks` 分别算（黑暗兵营那道门额外要求大本营局内等级 ≥2）；③ 抽出 `TryBuildBarracksStep(canNormal, canDark)`：**普通兵营槽优先 → 黑暗兵营槽 → 动态扩张按 40% 概率混搭**（保持"黑暗兵营不抢普通槽位"的原意图）；④ 新增 `IsSlotTypeAtCap`，槽位表兜底循环里跳过已达上限的类型 |

### R1.16 — 修「旧备份被错误淘汰」（会悄悄吃掉你的回退点）

**问题**：`TrimBackups()` 是"整个目录按文件名排序、删掉前 N 个"。而文件名是
`StageN_yyyyMMdd_HHmmss_原因.asset` —— **关卡名前缀主导排序，时间戳根本轮不到**。
所以删掉的不是最旧的备份，而是"名字靠前的那个关卡"的备份，并且会一路删到它一份不剩。

**实测**（就是 `StageBackups\` 里那 19 份的真实文件）：

| | |
|---|---|
| 代码会先删 | `Stage1_20260930_131929_保存前.asset`（2026-09-29）|
| 全目录真正最老的 | `Stage2_20261004_224958_保存前.asset`（2026-09-25，**反而活着**）|
| 继续下去 | 把 Stage1 的 **9 份全删光**（含最新那份），才轮到 Stage2 |

19 份、上限 20 —— **下一次保存就触发**。而备份是"保存前自动备份 / 一键修复前 / 恢复前"唯一的兜底，
它被悄悄吃掉意味着出事时想回滚却发现没得回。

**第二个洞**：清理用 `*.asset` 通配、**不校验文件名**。备份目录可以在设置页改成任意文件夹 ——
指到 `Assets\RemoteResource\Stages` 再触发一次备份，就会按份数上限**删掉那里的关卡资产**。

**修法**（与建筑 / 兵种编辑器同一套做法，那两个工具早有这个修复）：

| 改动 | 说明 |
|---|---|
| 按**关卡名**分组，各自保留最新 N 份 | 分组内前缀相同、时间戳定宽 → 名字序就是时间序 |
| 只清理**认得出是备份**的文件 | `TryParseBackupName()` 认 `关卡名_yyyyMMdd_HHmmss_原因.asset`（关卡名可带下划线，用「第一组 8 位日期 + 6 位时间」定位时间戳）；认不出的一律不碰 —— `Stage2.asset` 这种真资产天然认不出 |
| 设置项文案改成「**每个关卡**保留份数」 | 语义从"全目录 N 份"变成"每个关卡 N 份"，文案必须跟上，否则这个选项是误导的 |
| `ListBackups()` 注释改成实话 | 它本来就是按文件名倒序、不是按时间倒序（**只改文档，没改行为** —— 改排序有可能让原本能翻到的备份从菜单前 25 项里掉出去） |

#### R1.13a — 修 `ArgumentOutOfRangeException`（R1.13 首版留下的崩溃）

R1.13 首版写的是"清空后不 return，继续往下画"，理由是 `return` 会跳过 `EndScrollView`、
让滚动视图报 `Mismatched LayoutGroup`。**这个判断只对了一半** —— 继续往下画同样不行：

```csharp
int total = objects.Count;          // 本帧开头取的快照 = 12
...
config.objects.Clear();             // objects 现在是空表，total 还是 12
...
for (int i = 0; i < total; i++)
    StageObjectData data = objects[i];   // ← i=0 直接越界
```

`List<T>` 的下标越界抛的是 `ArgumentOutOfRangeException`（数组才是 `IndexOutOfRangeException`），
报错原文就是 `Index was out of range. Must be non-negative and less than the size of the collection.`
点一次「清空全部预摆对象」就必崩一帧，栈顶是 `LevelEditorWindow.DrawPlacedObjectsBlock`。

正确的做法是**两个都不选**：改完数据直接 `GUIUtility.ExitGUI()`，让本次 `OnGUI` 立刻收摊、
下一帧按新数据重新 Layout。这也是工程里已有的惯例（`WhiteBorderRemovalWindow.cs:240 / 249`
同样是"按钮改完数据就 ExitGUI"），而且它不在 `BeginScrollView / EndScrollView` 之间留下未配对的组。

顺带把聚合循环的边界从 `total` 改成 `objects.Count`：`total` 是给标题和告警条用的本帧快照，
**按下标取数据时永远不要用它**。

> 教训：IMGUI 里"改了正在画的这张表"有两条路可走 —— 要么让本帧的控件数量不变（像「清空白名单」
> 那样只是改标记），要么立刻 `ExitGUI()` 重排。最不该做的就是"改完接着按旧边界往下画"。

### R1.12 — 修「折叠点了没反应」（R1.10 缓存改造留下的回归）

反馈：**收缩功能无法使用** —— 点队伍左边的 ▼▶、点兵营/阶标题、点工具栏「全部收起」，界面都不动。

**根因**：R1.10 把折叠状态改成内存缓存 `FoldCache` 时，只改了**读**（`IsCollapsed` 先查缓存、未命中才读 `EditorPrefs`），
忘了改**写** —— `SetCollapsed()` 仍然只写 `EditorPrefs`，没有回写 `FoldCache`：

```csharp
// 错的（R1.10 ~ R1.11）
private static void SetCollapsed(string key, bool collapsed)
{
    EditorPrefs.SetBool(FoldPrefPrefix + key, collapsed);   // 缓存没动
}
```

于是每帧的 `IsCollapsed(key)` 永远命中那条旧缓存值，点击写进注册表的新状态**当帧就被丢掉**，
下一帧照样按旧状态画 → 视觉上就是"点了立刻弹回 / 完全没反应"。

> 这个 bug 只在**同一个编辑器域内**成立：`FoldCache` 是 `static`，域重载（改脚本、重开 Unity）会清空它，
> 那时才第一次从 `EditorPrefs` 读到之前写进去的值 —— 所以表现为"重开 Unity 之后折叠状态又对了"，
> 很容易被误判成"刷新问题"。

**修复**：`SetCollapsed()` 先写缓存再写 `EditorPrefs`（两处：`LevelEditorWindow.cs`，同源问题一并修掉建筑编辑器 `BuildingEditorWindow.cs`）。

```csharp
private static void SetCollapsed(string key, bool collapsed)
{
    FoldCache[key] = collapsed;                              // ← 缺的就是这一行
    EditorPrefs.SetBool(FoldPrefPrefix + key, collapsed);
}
```

「全部展开 / 全部收起」（`SetAllFold`）走的也是 `SetCollapsed`，所以那一对按钮同时恢复正常，中栏与右栏一起折。

> 教训：**带缓存的读，必须配一个写穿（write-through）的写**。只加缓存不改写路径，等于把状态改成了只读。
